# WTB-DefectNet Experiments

Experimental evaluation, ablation studies, performance analysis, and Explainable AI (XAI) visualizations for **WTB-DefectNet**, a deep learning framework for multi-class wind turbine blade defect classification.

---

## Overview

This repository contains the experimental results and evaluation of **WTB-DefectNet**, developed for automatic classification of wind turbine blade surface defects.

The repository documents the complete experimental workflow, including:

- Baseline and follow-up experiment results
- Training and validation curves
- Performance metrics
- Confusion matrices
- Explainable AI (Grad-CAM) visualizations
- Architecture-vs-documentation audits and fixes between experiments

## Experiment 1 — Baseline (`exp1`)

The first experiment establishes the baseline performance of WTB-DefectNet on the 9-class WTBs2025 wind turbine blade defect dataset.

### Training Configuration
- Architecture: WTB-DefectNet (standard-conv stem, single strided-conv downsampling, plain learnable prototypes)
- Number of Classes: 9
- Epochs: 120 (best checkpoint: epoch 120)
- Optimizer: AdamW
- Learning Rate Scheduler: Cosine annealing with linear warmup
- Loss: Class-balanced focal + logit-adjusted CE + prototype/center loss

### Test Performance
| Metric | Score |
|---|---|
| Accuracy | **70.71%** |
| Macro Precision | **63.43%** |
| Macro Recall | **68.72%** |
| Macro F1-Score | **65.37%** |
| Weighted F1-Score | **71.01%** |
| Balanced Accuracy | **68.72%** |
| Cohen's Kappa | **0.6416** |
| Matthews Correlation Coefficient | **0.6435** |

### Per-Class F1
| Defect Class | F1 Score |
|---|---:|
| Oil Leakage | **99.52%** |
| Erosion | **86.56%** |
| Lightning Strikes | **85.07%** |
| Protective Film Damage | **68.91%** |
| Pinholes | **63.25%** |
| Coating Detachment | **61.54%** |
| Paint Cracks | **48.89%** |
| Localized Damage | **46.28%** |
| Surface Stains | **28.35%** |

### Observations
**Strengths:** excellent detection of Oil Leakage; strong performance on Erosion and Lightning Strikes; stable convergence.
**Challenges:** Surface Stains, Paint Cracks, and Localized Damage are visually similar / texture-overlapping classes and remain the weakest categories.

## Experiment 2 — Doc-Alignment Pass (`Try_2`)

Try_2 rewrote three backbone components (`wtb/model.py`) to match `Proposed_Architecture.docx` more literally:

1. **DSPS (B1)** — dilated stem branches made genuinely depthwise (`groups=in_ch`) instead of standard convs, plus a residual-fusion shortcut.
2. **Transition Layer** — introduced as its own module (1×1 Conv → BN → Act → 2×2 AvgPool) between stages, replacing the single strided conv exp1 used.
3. **LTCP (B7)** — prototypes converted from a plain learnable `nn.Parameter` to a non-learnable buffer updated via EMA (`update_prototypes()`), matching the doc's "EMA Prototype Memory Bank" component.

### Test Performance
| Metric | exp1 | Try_2 | Δ |
|---|---:|---:|---:|
| Accuracy | 70.71% | 62.36% | **−8.35** |
| Macro Precision | 63.43% | 57.60% | −5.83 |
| Macro Recall | 68.72% | 65.39% | −3.33 |
| Macro F1-Score | 65.37% | 59.24% | **−6.13** |
| Balanced Accuracy | 68.72% | 65.39% | −3.33 |
| Cohen's Kappa | 0.6416 | 0.5502 | −0.0914 |
| MCC | 0.6435 | 0.5581 | −0.0854 |

### Per-Class F1: exp1 vs Try_2
| Defect Class | exp1 | Try_2 | Δ |
|---|---:|---:|---:|
| Oil Leakage | 99.52% | 99.52% | 0.00 |
| Paint Cracks | 48.89% | 41.86% | −7.03 |
| Localized Damage | 46.28% | 28.48% | **−17.80** |
| Lightning Strikes | 85.07% | 82.35% | −2.72 |
| Surface Stains | 28.35% | 27.38% | −0.97 |
| Erosion | 86.56% | 76.49% | **−10.06** |
| Coating Detachment | 61.54% | 60.29% | −1.25 |
| Protective Film Damage | 68.91% | 54.86% | **−14.05** |
| Pinholes | 63.25% | 61.89% | −1.36 |

### Root Cause
Nearly every class regressed — not only the rare/fine-grained ones the EMA prototype change specifically targeted (lightning-strike recall, in fact, stayed intact: 98.25% recall in Try_2 vs 100% in exp1). That pattern pointed away from LTCP and toward the two capacity-affecting changes:

1. **DSPS rank-3 bottleneck.** The depthwise dilated convs used `groups=in_ch=3` with `out_channels=in_ch`, giving exactly one filter per RGB channel per dilation rate — only 3 linearly-independent spatial patterns per branch, regardless of how wide the pointwise projection after it was.
2. **Transition Layer AvgPool blur.** The doc actually lists this step as *"2×2 Average Pooling (or Strided Convolution)"* — AvgPool was only one of two allowed options, and plain averaging smeared exactly the fine crack/pinhole boundaries the network needs to keep, at all three stage transitions.

Train accuracy stayed at ~74% throughout (see `runs/Try_2/log.csv`), so this was underfitting the *representation* (weak stem/downsampling features) rather than the optimization failing to converge.

## Experiment 3 — Capacity-Bottleneck Fixes (`Try_3`, in progress)

Try_3 keeps the doc-aligned architecture from Try_2 but fixes the two issues identified above, plus adds light regularization to offset the resulting capacity increase:

1. **DSPS**: depthwise multiplier increased from 1 → 8 (24 independent filters per branch instead of 3), still `groups=in_ch` as the doc's Novelty section specifies. Restructured to concatenate all 4 branches before a single 1×1 pointwise fuse, matching the doc's stated component order.
2. **Transition Layer**: switched from AvgPool to the doc's other listed option — a learned stride-2 depthwise conv — so edge-relevant activations survive stage downsampling instead of being averaged away.
3. **Head dropout** (0.15): added on the logits pathway only; the raw features used by the prototype/center loss and the EMA prototype update stay clean so rare-class handling isn't affected.

Results for this run will be added here once training and evaluation (`runs/Try_3/eval/`) complete.
